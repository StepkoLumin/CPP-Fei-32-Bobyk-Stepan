# CrossApp
Наскрізний проєкт з крос-платформного програмування.

## Предметна область
**Склад**. Сутності: Product (товар), StockBatch (партія), Warehouse (склад), Movement (переміщення).
Призначення: облік залишків товарів по партіях.

*Домовленість про каталоги в Core (на майбутнє):*
- `Core/Dto/` — record-типи формату даних
- `Core/Domain/` — сутності з поведінкою та інваріантами
- `Core/Storage/` — реалізації сховищ

## Структура Solution
- `src/Cli` — точка входу (консольний застосунок).
- `src/Core` — спільна бібліотека (Class Library) з допоміжною логікою.

## Команди для роботи
- **Збірка:** `dotnet build`
- **Запуск:** `dotnet run --project src/Cli`
- **Публікація (Framework-dependent):** `dotnet publish src/Cli -c Release -r win-x64 --self-contained false`
- **Публікація (Self-contained):** `dotnet publish src/Cli -c Release -r win-x64 --self-contained true`

## Порівняння режимів публікації (win-x64)
| Режим | Розмір publish | Потрібен встановлений runtime |
| :--- | :--- | :--- |
| Self-contained | ~70 МБ | Ні |
| Framework-dependent | ~0.2 МБ | Так (.NET 10) |


## Формат вхідних даних (Лабораторна робота 3)
- **Формат:** CSV
- **Роздільник:** Крапка з комою (`;`)
- **Кодування:** UTF-8
- **Наявність заголовка:** Так (перший рядок пропускається парсером, якщо починається з "id")

## Доменна модель та інваріанти (Лабораторна робота 4)
У проєкті реалізовано доменну модель із захистом стану (інкапсуляцією). Створення об'єктів відбувається виключно через статичний фабричний метод `Create`, а зміна стану — через спеціалізовані методи (`RegisterArrival`, `Issue`). 

### Перелік інваріантів доменної моделі (Product)
1. **Ідентифікатор та SKU не можуть бути порожніми.**
   - *Тип винятку:* `ArgumentException`
   - *Де перевіряється:* У фабричному методі `Create`.
2. **Кількість (залишок) не може бути від'ємною.**
   - *Тип винятку:* `ArgumentOutOfRangeException`
   - *Де перевіряється:* У методі `Create` (при початковому створенні), а також у методах `RegisterArrival` та `Issue` (кількість операції має бути > 0).
3. **Неможливо видати товару більше, ніж є на залишку.**
   - *Тип винятку:* `InvalidOperationException`
   - *Де перевіряється:* У методі `Issue`. Операція заборонена в поточному стані об'єкта.

# CrossApp - Лабораторна робота №5

## Архітектурний опис (Сервісний шар та ручний DI)

Проєкт реалізує принципи **Clean Architecture** та **Принцип інверсії залежностей (DIP)**. Доменна логіка повністю відокремлена від деталей збереження даних завдяки використанню абстракцій.

### Основні компоненти:
- **Інтерфейс сховища:** `ICatalogStore` (розташований у `src/Core/Abstractions/ICatalogStore.cs`) — визначає контракт взаємодії (методи `List`, `GetById`, `Add`, `Update`, `Remove`).
- **Реалізації сховища:**
  - `InMemoryCatalogStore` — зберігає дані в оперативній пам'яті за допомогою `Dictionary`.
  - `FileCatalogStore` — забезпечує персистентність на диску у форматі JSON (`data/catalog.json`) із механізмами кешування та `Flush`.
  - `CachingCatalogStore` — декоратор для оптимізації звернень до сховища (опціонально).
- **Бізнес-сервіс:** `CatalogService` (розташований у `src/Core/Services/CatalogService.cs`) — містить доменні операції (`Add`, `Receive`, `All`, `Find`), залежить виключно від інтерфейсу `ICatalogStore`.
- **Composition Root та Фабрика:** Точка входу `Program.cs` спільно з `StoreFactory` виконує ручне впровадження залежностей (Manual Dependency Injection) та дозволяє перемикати режими роботи сховища за допомогою аргументу командного рядка `--file`.
